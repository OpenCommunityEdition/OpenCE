## `_hud_show_action_response`

No shape was spent, because the function is on the do-not-repeat list and no new law applies:

- A3 is the w2 S5 shape, which measured worse.
- A10 does not apply: January keeps `allow_swap_prompt` in CL, as ours does.
- A9 switch widths are already identical.

The whole-function alignment is in `scratch/workers/w3_hud_nav_points_hud_etc/sar_full.aln`. It shows that every non-register difference follows from the entry register assignment (parameter in EDI, `item_name_index` in EBX):

1. January delays (shrink-wraps) the EBX push to +0xc3.
2. In the default arm, EBX is free for `weapon_index`. That lowers the stack slot's references from 4 to 3 and swaps the `[ebp-4]` and `[ebp-8]` slots.
3. Because EBX is occupied, January re-reads `unit->unit.parent_seat_index` after the `unit_get` call, while ours keeps it in BX.

None of these is an independent source lever. The reopen criterion is unchanged.

## `_temporary_hud_draw_reticle`

New evidence from this wave:

**A5 detector (hand strength reduction) on the second loop: refuted by measurement.**
- The natural indexed `for` compiles to `cmp eax,0x10; jb` and gives 192. This holds with `% 16` (t1) and with `% NUMBEROF` (t2).
- Both lose January's three-induction-variable loop latch `inc esi; add edi,0xc; dec ebx; jne`.
- So the do-while already in the file is January's form.

**January-wide x87 flush census** (`scratch/workers/w3_hud_nav_points_hud_etc/x87flush_scan.py` and `.txt`). The census counts two patterns after a cdecl call:

| pattern | form | occurrences | base-exact |
| --- | --- | --- | --- |
| `fld m; fOP m; add esp` | January's reticle form | 154 | 83 |
| `fld m; add esp; fOP m` | our form | 15 | 10 |

- January-form sites are compound stores on locals or local struct fields, e.g. `color.red *= 0.8f` in `_render_debug_light`.
- Our-form sites include compound stores on pointer fields and on parameters.
- No site isolates a source lever for a scalar loop accumulator.

**Diagnostics.**
- e2 takes the accumulator's address. The fadd is still deferred past the next push, so enregistration is not the cause.
- e3 uses a one-element array as the accumulator. It is identical to w2 r1.

The signed remainder still has no admitted spelling:
- `(long)NUMBEROF` was rejected under R7.
- A `% 16` literal or a TU-local count define would need a ruling.

Reopen criterion: a same-compiler donor for the scalar-accumulator schedule, plus an admissible signed-divisor spelling.
