## Shape 1: original private parameter order

The current reconstruction placed `geometry` before `projection`. HCEA's actual named function signature instead reads:

```c
static void decal_clip_to_surface(
    struct decal_projection const *projection,
    struct decal_geometry *geometry,
    /* eight remaining parameters unchanged */);
```

Raw `/Od` code independently confirms this: `0x566a33` checks `[EBP+8]` using the assertion string `projection` (PE address `0x95d1b4`), then `0x566a5d` checks `[EBP+0xc]` using `geometry` (`0x95d1f4`). Both caller sites push geometry before projection, placing projection first on the stack: `0x569472..0x56947e` and `0x569e86..0x569e92`. Both clean ten arguments with `ADD ESP,0x28`.

The January optimized ABI promotes geometry to EAX while projection remains the first stack argument. That register promotion cannot determine whether geometry was source argument one or two. The probe corrects both static declarations and both calls. Every one of 152 defined owners, including all 55 functions, remains byte-and-relocation equal to baseline. This proves the signature correction is compatible with January, but it does not explain the clip scheduling residual. Other private helpers may share this ambiguity; no other file was changed or researched in this packet.

## Shape 2: failure exits belong to the chain loop

Current source returns directly on nonpositive geometry, failed vertex allocation, failed decal insertion, and failed vertex lock. Fresh raw `/Od` code instead stores `NONE` to the original `decal_definition_index` argument at `[EBX+8]` and returns to the enclosing chain condition:

| Raw address | Operation |
| --- | --- |
| `0x568768` | Loop compares `decal_definition_index` to `NONE` |
| `0x56a9bb` | Store `NONE` after vertex deletion for lock failure |
| `0x56a9ed` | Store `NONE` after vertex deletion for insert failure |
| `0x56aa2a` | Store `NONE` for allocation failure, before debug output |
| `0x56aa66` | Store `NONE` for nonpositive geometry counts |
| `0x56aa6d` | Common backedge to `0x568768` |

The candidate restores the positive geometry conditional with an `else` storing `NONE`, and the three allocation/insert/lock stores. The unrelated earlier hardware-format failure still returns directly. Success still stores the reuse flag and advances to `definition->next_decal_in_chain.index`.

All four failure paths reach only closing scopes and the outer loop test; no body side effect occurs after their terminal `NONE` store. They then reach the function's existing final return. These are meaningful loop-termination assignments authenticated independently of their byte effect, not dummy stores or artificial pressure variables.

**January qualification:** its optimized failure arms already jump to epilogues. January does not retain four explicit `NONE` stores. The source stores are directly established by the `/Od` build, and VC7 optimizes them away in this candidate too. Therefore the statement is source-CFG correspondence compatible with January's optimized exits, not a claim that January contains these four stores.
