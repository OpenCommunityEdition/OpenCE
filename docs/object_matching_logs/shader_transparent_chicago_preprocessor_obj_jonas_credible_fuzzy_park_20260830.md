# `shader_transparent_chicago_preprocessor.obj` credible fuzzy park

## Outcome

- `_shader_map_verify`: strict exact, 16 padded bytes, zero relocations.
- `_shader_transparent_chicago_create`: honest fuzzy park, 432 target bytes
  versus 416 candidate bytes, with all 17 relocation identities retained.
- `_shader_transparent_chicago_combiner_table`: strict exact, 208 bytes and no
  relocations.

No fabricated source was added to obtain those results. The retained create
function is the ordinary-C fixed point established by the 28-experiment ledger.

## Naming provenance

The symbol atlas entry for the September 25, 2001 Xbox build records
`shader_map_verify` as the first function in
`shader_transparent_chicago_preprocessor.obj`, immediately followed by
`shader_transparent_chicago_create`. This recovers the placeholder leaf name
from the same compiland and relative order. The January atlas separately names
a different `shader_map_verify` in the generic-shader preprocessor; that entry
was not misapplied to this address.

No surviving source symbol was found for the 208-byte constant payload.
`shader_transparent_chicago_combiner_table` is therefore a descriptive name,
chosen from its measured layout and use, rather than a claim about Bungie's
exact spelling.

## Source-credibility audit

The final source uses `TEST_FLAG`, `_error_silent`, real engine types, typed tag
block access, and declaration-time initialization. It contains no assembly,
raw-byte emission, compiler barrier, volatile type pun, inert cast, empty branch,
self-assignment, unreachable-code trick, or deliberately false semantic logic.

Making the dead 16-byte leaf `static` causes this VC7 invocation to eliminate
it. The January executable has no direct call or absolute pointer xref to that
leaf, so no honest source-level retention edge can be reconstructed. The source
therefore does not invent a fake table, call, or pragma to keep a static body.

## Residual mechanism

January keeps the known-true return value in `AL` at the bottom of the map loop
and carries the incremented map index in `ECX`. Both available compatible VC7
builds put the result in a stack home and use `EAX` for the increment. The
candidate is otherwise identical through the loop body, preserves all 17
relocation destinations, and owns exact data.

Twenty-eight documented source/compiler experiments did not reproduce the joint
allocation. Several explicit attempts to anchor `TRUE` merely hoisted a memory
store or changed wider control flow. Under the current house rule, the coherent
source is parked rather than replacing it with compiler steering.

## Reopen criteria

Reopen only for authoritative January source, a strict same-topology VC7 donor,
or a newly recovered compatible compiler/QFE. A candidate must preserve the
exact leaf, exact table, established loop semantics, and relocation identities
without source that exists only to influence instruction selection.
