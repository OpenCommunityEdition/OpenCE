## Evidence and mechanism

### The "private EAX convention" is the callee-register-pressure law

The parked ledger treated January's `mov eax, edi; call _hud_show_action_response` as an unexplained ABI. It is the measured VC7 law from codegen-levers-20260906: VC7 invents register conventions for file statics, and the callee's own register pressure decides which parameters are promoted.

January's callee never caches the player fields in locals. Every switch case re-reads `[esi+0x24]` (`player->action_object_index`), and the default arm re-reads `[esi+0x34]` (`player->unit_index`) before each call.

The baseline source cached both in `long action_object_index` / `long unit_index` locals. Those locals took a callee-saved register, which pushed `player_index` onto the stack. Writing `player->action_object_index` / `player->unit_index` at each use gives the static its EAX parameter naturally (size 1728 → 1744).

### Caller `_hud_draw_screen`

The else arm in January is `je 0xfe … push 0; push esi; call _hud_play_unit_sounds`: it passes a constant FALSE. That proves a nested form:

```c
if (hud_scripted_globals->show_hud)
{
	if (perspective != neutral && perspective != scripted && player->unit_index != NONE)
		{ full HUD }
	else
		{ hud_show_action_response(player_index); hud_play_unit_sounds(player, hud_scripted_globals->show_hud); }
}
else
{
	hud_play_unit_sounds(player, FALSE);
}
```

The HCEA `hud_draw_screen.c` has the same shape: `show_hud = 0` in its else arm. With the EAX callee in place, the result is 112/112 instructions with no differences. The minimal proof is `scratch/workers/hud/min1.c`: the v1 callee change plus this caller is already enough for EXACT.

### Further structural recoveries in `_hud_show_action_response`

- **Case order.** Block layout (0x108, 0x137, 0x18c, 0x1d5, 0x24f, 0x2f1, 0x393, 0x413, 0x44c) is the source case order: pickup, swap_for_powerup, exit_vehicle, touch_device, swap_for_weapon, add_weapon_to_inventory, enter/evict, flip, default. Reordering removed the extra relocation (121 → 120).
- **touch_device polarity.** January tests `custom_name_index != NONE` first: `je` goes to the touch arm.
- **`weapon_state_is_depleted` returns `boolean`.** Both callers test `al`, not `eax`. The callee stays exact (48 / sha `5d58458d…`).
- **`item_name_index` is assigned by explicit if/else.** January stores a word then reloads the dword (`mov ax,[eax+0x13c]; mov word [ebp-4],ax; mov ebx,[ebp-4]`). Inlining the long-returning `get_object_icon_text_index` gives `movsx` instead.
- **Each respawn-failure case ends in `return;`.** January cross-jumps the combat case into the vehicle case's tail. The `break` form keeps the first block instead.

### `_temporary_hud_draw_reticle`

The park evidence said VC7 "proves the index nonnegative". That is refuted: `NUMBEROF` is `size_t`, so the baseline `% NUMBEROF(points)` is an unsigned remainder, which lowers to `and eax,0xf`. January's generic signed-remainder sequence is `% (long)NUMBEROF(points)`. With that change (r1) the function is 208/6 with 77/77 instructions.

The only remaining difference: January emits `fld [ebp+8]; fadd pi/8` before the deferred `add esp,0xc` after `matrix4x3_transform_point`, and ours emits it after. Five tie shapes were inert:
