## January ownership and ABI

The complete relocation census gives a compact, real caller cluster:

- `compare_profile_sections` has exactly one incoming relocation, from
  `profile_dump+234`;
- `header_strings` has one incoming relocation, from `profile_dump+293`;
- `format_strings` has two incoming relocations, from `profile_dump+727` and
  `profile_dump+775`;
- `profile_dump` has exactly two January callers:
  `profile_dump_to_file+86` and Interface `_code_000cea10+480`.

The Interface caller pushes `buffer`, maximum count `10`, format mode `1`,
sort mode `2`, and a null name.  `profile_dump_to_file` pushes its buffer,
count `256`, format mode `0`, boolean name-sort mode, and `name`.  The January
callee sign-extends the three mode/count arguments from 16-bit stack slots.
The supported public declaration is therefore:

```c
void profile_dump(
	const char *name,
	short sort_mode,
	short format_mode,
	short maximum_section_count,
	char *buffer);
```

The current consumer-local declaration in `profile.c` incorrectly spells the
three narrow arguments as `long`; it is not an acceptable integration route.

The two arrays are separately named, private arrays of two pointers each:

```c
static const char *header_strings[NUMBER_OF_PROFILE_DUMP_FORMAT_MODES];
static const char *format_strings[NUMBER_OF_PROFILE_DUMP_FORMAT_MODES];
```

They intentionally use pointers to const characters rather than const
pointers: January's combined 16-byte/four-relocation contribution is writable
`.data`.  Both candidate symbols cover the same contribution at offsets zero
and eight.  Its normalized hash is
`374708fff7719dd5979ec875d56cd2286f6d3cf7ec317a3b25632aab28ec37bb`
in both January and the candidate.  January's split metadata defaults the
owners external; the sole real source consumer and the frozen donor support
private/static linkage.  Root must make any target metadata correction

## Recovered behavior

`profile_dump` performs the complete January operation rather than a display
stub:

1. validate sort mode, format mode, positive output count, and output buffer;
2. copy the current section-pointer array and `qsort` it with the private
   comparator;
3. require an active first sorted section before emitting the selected header;
4. group adjacent equal names and aggregate cumulative calls/time, per-sample
   calls/time, peaks, and current-frame calls/time;
5. optionally filter names with `strstr`;
6. emit either the file or on-screen format using the real enum constants and
   the January `(long)(average_calls+0.5f)` display conversion.

The comparator places active sections first, then implements:

- `_profile_sort_mode_name`: `csstrcmp` ascending;
- `_profile_sort_mode_average_time`: elapsed-timebase/sample-count descending,
  treating a zero sample count as zero;
- `_profile_sort_mode_total_time`: the signed 64-bit rolling/recent elapsed
  total at offset `0x20`, descending.

An invalid mode executes the target-backed `!"unreachable"` assertion and
then returns the initialized result (`0`) if the fatal path unexpectedly
returns.  January instead returns the first argument's low pointer bits after
`system_exit(-1)`; the donor reproduced this through an uninitialized local.
That unreachable-byte detail is preserved as evidence only, not source.

January also leaves `buffer` untouched when no active section exists and uses
unbounded `sprintf` appends.  Those are target-established behaviors/risks;
the reconstruction does not invent a safer but different contract.

## Semantic owner-field proposal

The dump should not be admitted using address-style structure members.  The
scratch owner-header proposal renames fields from the complete January
read/write topology:

| offset | proposed name | evidence |
|---:|---|---|
| `0x18` | `recent_call_count` | subtract old history slot, add current frame |
| `0x20` | `recent_elapsed_timebase` | same rolling operation for 64-bit ticks; comparator mode 2 |
| `0x28` | `frame_call_count_history` | 120-entry history indexed by `history_index` |
| `0x208` | `frame_elapsed_timebase_history` | 120-entry 64-bit history |
| `0x5C8` | `sample_count` | increments once per active section update and is the average denominator |
| `0x5D8` | `total_call_count` | cumulative calls used by dump |
| `0x5E0` | `total_elapsed_timebase` | cumulative ticks used by dump |
| `0x5E8` | `peak_call_count` | max current-frame call count |
| `0x5F0` | `peak_elapsed_timebase` | max current-frame elapsed ticks |

The scratch overlay preserves the exact `0x5F8` layout and every asserted
