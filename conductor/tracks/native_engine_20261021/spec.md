# Spec: A new native engine in Rust and Swift

## Overview
Today's app runs the decompiled Xbox game in a 32-bit VM (Hypervisor.framework) because the game's C and its map files use 32-bit pointers at fixed Xbox addresses. That design keeps the original's limits: a fixed resolution and aspect ratio in the UI, weak anti-aliasing, a controller-shaped interface, and a cost of about 1 µs for every exit to the host.

This track builds a new engine from scratch:

- **Rust** owns content, simulation, scripts, physics and the network.
- **Swift** owns the app, input, the Metal renderer, the menus and the audio.
- **C** is used only where a library needs it (the Jolt wrapper).
- **Nix** builds it.

Nothing runs at fixed addresses, there is no VM, and every pointer is 64-bit. The decompilation in `source/` becomes a reference for how the game behaves; its code is not compiled into the new engine. The user's Xbox and Custom Edition maps become content that the engine imports once into a typed, native format.

The original is not preserved. Behaviour that players feel is matched against the reference app: movement speeds, jump height, weapon timing, damage and vehicle handling. Everything else is free to be modern: the resolution, the aspect ratio, the anti-aliasing, the lighting, the menus and the physics.

The work follows seven milestones, each a phase that ends with something playable or viewable. The current app (`nix build .#app`) stays buildable as the reference and the benchmark until the new engine reaches parity.

## Functional Requirements

### Foundations
1. **Layout.** The new engine lives in `engine/`:
   - a Cargo workspace (`engine/crates/`): `content`, `import`, `sim`, `physics`, `script`, `net` and `ffi`;
   - a Swift package (`engine/app/`).

   Nix builds it as `nix build .#engine`, which makes `OpenCE Engine.app` until the final phase renames it.
2. **The contract.** One contract between Rust and Swift, defined in Rust:
   - **UniFFI** carries calls: load a map, start a game, input, settings.
   - Per-frame data (the render snapshot, the HUD state, sound events) goes through `#[repr(C)]` types in a header generated by cbindgen. Swift reads the snapshot without copying it.

   Swift never sees the simulation's internals.
3. **The simulation.** A `bevy_ecs` world (the `bevy_ecs` crate only, not the Bevy engine), stepped on a fixed tick of 60 Hz. The renderer interpolates between the last two ticks at the display's rate. Systems run in a fixed order, so a run repeats exactly from the same inputs.
4. **Determinism.** The simulation's maths is deterministic: no fused multiply-add, and functions of our own or vendored (`libm`) rather than the platform's. A test replays a recorded input file and checks a hash of the world after N ticks.

### Milestone 1: Import a map and fly through it
5. **Importing.** `import` reads Xbox cache files (`assets/maps/*.map`) and Custom Edition caches (`custom_maps/` with `bitmaps.map`, `sounds.map` and `loc.map`) through bounds-checked readers. It turns their tags into typed Rust structures in `content`. A malformed file is refused with an error naming the tag and the field, and never panics. The layouts come from the decompilation and `docs/custom_edition_caches.md`.
6. **The native format.** Imported content is written to a versioned file of our own (`.ocpak`), one for each map plus one for the shared data. It is an `rkyv` archive whose validation (`bytecheck`) runs on every load, so the files are untrusted input too. Bitmaps are converted on import to formats Metal samples directly (BC1–BC5 kept, the rest to RGBA8 or BC7), with mipmaps. A cache of imports in the data folder is rebuilt when the importer's version changes.
7. **The Metal viewer.** The app opens a window or goes full screen at the display's native resolution and any aspect ratio, including ultrawide, and draws the structure BSP with its lightmaps and its shaders mapped to modern materials. A free camera flies with the mouse and keyboard, with the cursor captured.
8. **The renderer's base:**
   - HDR rendering, shown in EDR where the display supports it and tone-mapped elsewhere;
   - MetalFX temporal anti-aliasing and upscaling, with a native-resolution mode;
   - a Hor+ field of view (the horizontal angle grows with the aspect ratio);
   - frame pacing to the display's refresh rate (ProMotion included).

### Milestone 2: Objects, models and animation
9. The scenario's objects are spawned in the world: scenery, weapons on the ground, vehicles, machines and controls, and bipeds standing.
10. Their models are drawn with their permutations, regions and levels of detail. The engine plays their animations from the imported animation graphs: blending, overlays, and node matrices computed in Rust and handed to Swift in the snapshot.
11. The skies, fog, transparent shaders, decals on the level, and the particles and effects that scenery plays.

### Milestone 3: Player movement and collision
12. A player biped moves with the keyboard and mouse: walk, run, crouch, jump, and look with raw mouse input and an adjustable sensitivity, with no acceleration. Collision is against the structure BSP and the objects.
13. Movement matches the reference app within a set tolerance for:
    - speeds;
    - acceleration;
    - jump height;
    - fall damage;
    - stepping up;
    - sliding on steep surfaces.

    This is checked against traces recorded from the reference app.
14. **Physics:** Jolt (the vendored copy) behind a Rust crate (`physics`) that calls our C wrapper. Players use Jolt's `CharacterVirtual`, tuned from the biped tags. The static world is a Jolt mesh built from the imported collision BSP.

### Milestone 4: Weapons, damage, grenades and ragdolls
15. **Weapons.** Picking up, swapping and dropping weapons. Firing, with the weapon tags' rates, spread, heat, ammunition and reloads. Projectiles and hitscan, melee, and the first-person view with its animations.
16. **Damage and death.** Damage and its effects, with shields and health, hit regions, and the damage tags' effects (camera shake, impulses). Grenades are thrown and bounce, with frags and plasma that sticks.
17. **The HUD.** Drawn by Metal at native resolution and anchored to the screen's edges at any aspect ratio: the crosshair, ammunition, shields, the motion tracker and messages.
18. **Ragdolls.** Every biped becomes a Jolt ragdoll when it dies. Motors follow the death animation, then damping lets the body go loose, so it does not look stiff. Corpses persist up to a cap, which is a setting with a high default, and the oldest go first. Explosions can tear off limbs, as the ragdoll track does now. Debris and casings are rigid bodies.

### Milestone 5: Vehicles
19. The Warthog, the Scorpion, the Ghost, the Banshee and Custom Edition vehicles:
    - driving and flying;
    - the seats, entering and leaving, turrets and passengers;
    - damage and their destruction.

    Ground vehicles use Jolt's vehicle constraints, tuned from the vehicle tags, and their handling is compared against traces from the reference app.

### Milestone 6: Multiplayer
20. **Slayer and CTF** on the stock and Custom Edition multiplayer maps, for up to 16 players, over UDP on a LAN or by address.
21. **The netcode.** Only the host decides. Clients predict their own player and reconcile with the host's snapshots. Snapshots are delta-compressed and every packet is checked as untrusted (sizes, indices, rates). A protocol version is raised with any change to what machines send. Two copies on one machine (loopback aliases) test it.
22. **The menus.** Main menu, server list and join, host setup, the game's settings, controls, video and audio. They are native, at the screen's resolution, and made for a mouse: SwiftUI over the Metal view, with Overpass and the OpenCE font.

### Milestone 7: AI and the campaign
23. **HaloScript.** The scenario's compiled script nodes are imported into a typed tree and run by an interpreter in Rust (`script`). Every function and global is declared with its types; a script that names one the engine lacks is reported on import. `source/hs/` is the reference.
24. **The AI.** Encounters, squads, actors and their types, firing positions, command lists, and perception, combat and vehicle use. Behaviour is compared against the reference on chosen encounters.
25. **The campaign.** Its flow: BSP switches, checkpoints and saved games (in a format of our own), cutscenes (the camera points and the scripts), and the difficulties. The milestone is met when *The Pillar of Autumn* and *Halo* can be played from start to end.

### Settings and data
26. **Settings** live in one typed Rust structure, saved as TOML in `~/Library/Application Support/OpenCE/`, and shown in the settings menus. Departures from the stock game need not be off by default.
27. **Game data** stays the user's own: the importer reads it from the data folder, and nothing from it is shipped or committed.

## Non-Functional Requirements
- **Performance:** 3840×2160 (or the display's native size) at 120 fps or more on the M1 Max. The bar is p99 ≤ 8.33 ms in a 60-second benchmark on bloodgulch, from milestone 2 on. A simulation tick costs ≤ 2 ms with 16 players and 30 ragdolls.
- **Safety:**
  - Rust has no `unsafe` outside `ffi` and `physics`, and every `unsafe` block has a `// SAFETY:` comment.
  - Maps, `.ocpak` files and packets are untrusted. Fuzz targets cover the importer and the packet decoder.
- **Typing:** tags, handles and indices are typed. An object handle cannot be used as a tag handle, and units are named where they are confusable (`WorldUnits`, `Seconds`, `Radians`).
- **Extensibility:** a new object kind, weapon behaviour or HaloScript function is added in one place and registered with its system, without editing a central switch.
- **Coverage:** above 80% for new Rust and Swift code (`cargo llvm-cov`, XCTest).
- **Tests without game data:** content is built in tests from small builders. Tests that need `assets/maps` are marked and skipped without it.
- **Licences:** the code is CC0. Rust dependencies come from crates.io, pinned by `Cargo.lock` and vendored by Nix. Their licences are permissive (MIT, Apache-2.0, BSD, Zlib, CC0), checked by `cargo deny`. No GPL code, and no Xbox SDK headers.

## Acceptance Criteria
1. `nix build .#engine` builds `OpenCE Engine.app` from a clean checkout, and `nix build .#app` (the reference) still builds.
2. **Milestone 1:** every stock map and a set of Custom Edition maps import without error. A corrupted copy of each is refused without a panic, which the fuzzing confirms. Golden frames come from the viewer at 1920×1080, 3440×1440 and 3840×2160 at fixed cameras.
3. **Milestone 2:** golden frames of bloodgulch's and a campaign map's objects and animated bipeds. The benchmark meets the performance target.
4. **Milestone 3:** movement traces fall within tolerance of the reference app's: run, jump, crouch, fall, and climb a ramp.
5. **Milestone 4:** weapon timing tests (rate, reload, heat) match the tags. A scripted grenade kill leaves a ragdoll that settles loosely and stays. The HUD is anchored correctly at 16:9, 16:10 and 21:9.
6. **Milestone 5:** Warthog and Ghost handling traces fall within tolerance of the reference app's. Entering, leaving and the turrets work in a scripted test.
7. **Milestone 6:** two copies play Slayer and CTF on loopback with prediction, and a test with corrupted packets (the decoder fuzzed) shows them handled. The menus work with the mouse alone.
8. **Milestone 7:** every stock scenario's scripts import, or name the functions they lack. The first two campaign levels play from start to end in a recorded run.
9. The full test suite passes inside `nix develop`. `docs/engine.md` describes the architecture, the contract, the content format and how to add an object kind, a weapon behaviour and a script function.

## Out of Scope
- Keeping the decompiled C running in the new engine, or matching the original byte for byte.
- Ray-traced lighting: the existing track is re-planned onto the new renderer after this track.
- Internet play through brokers, NAT traversal and WebRTC; voice chat; map sharing; mods. These are later tracks.
- Gamepads and touch: keyboard and mouse only.
- Platforms other than macOS on Apple Silicon.
- Removing the reference app: a later track, once the new engine plays the campaign and multiplayer.
- OpenSauce features in Custom Edition maps.
