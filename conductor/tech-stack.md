# Tech Stack: OpenCE (macOS)

## The New Engine (`engine/`, track `native_engine_20261021`) — **Added 2026-10-21**
The engine is being rebuilt from scratch in Rust and Swift, with no VM, no 32-bit addressing and no fixed addresses. The decompiled C in `source/` becomes a reference for behaviour and is not compiled into the new engine. The VM app described below stays buildable (`nix build .#app`) as the reference and the benchmark until the new engine reaches parity.
- **Rust (stable 1.98, edition 2021): a Cargo workspace in `engine/`.**
  - `content`: typed tag structures.
  - `import`: bounds-checked readers for Xbox and Custom Edition caches, and the `.ocpak` writer.
  - `sim`: the world, using the `bevy_ecs` crate alone (not the Bevy engine), on a fixed 60 Hz tick.
  - `physics`: Jolt, through the existing C wrapper.
  - `script`: HaloScript, run at Halo's 30 Hz on every second simulation tick.
  - `net`: host-authoritative UDP play with prediction.
  - `campaign`: a mission — the scenario's scripts over the simulation, the AI's actors, the game's flow and saves.
  - `ffi`: the contract with Swift.
- **The content format:** `.ocpak` files, `rkyv` archives checked with `bytecheck` on every load (they are untrusted).
- **The contract between Rust and Swift.**
  - UniFFI carries the calls: load, start, input, settings.
  - Per-frame data goes in `#[repr(C)]` snapshot types, through a header generated by cbindgen. Swift reads it without copying.
- **Swift: the app (`engine/app`).**
  - AppKit windowing with a `CAMetalLayer`: full screen at any aspect ratio, cursor capture and raw mouse input.
  - The Metal renderer: HDR shown in EDR, MetalFX temporal anti-aliasing and upscaling, and a Hor+ field of view.
  - The menus and settings in SwiftUI over the Metal view, designed for a mouse.
  - Sound through AVAudioEngine.
- **Determinism:** the simulation's maths uses `libm` (Rust) and our own functions, never the platform's, with no fused multiply-add. A replay of recorded inputs checks a hash of the world.
- **Dependencies:** crates from crates.io, pinned in `engine/Cargo.lock` and vendored by Nix (`importCargoLock`). Their licences are checked by `cargo deny`: MIT, Apache-2.0, BSD, Zlib, ISC, Unicode or CC0 only.
- **Testing:** `cargo test` and `cargo fuzz` (the importer and the packet decoder), plus XCTest for the Swift layer. Golden frames are rendered offscreen. Traces recorded from the reference app check movement, vehicles and the AI.

## The Reference App (VM)

## Game Core (kept)
- **C (C89, `gnu89`)**: the decompiled game in `source/` and the shared port layer in `port/linux/src` and `port/linux/game`.
- **Guest ABI: ILP32 AArch64** (`arm64_32-apple-watchos` via Nix's clang 22 (unwrapped) and lld, the assembly converted to ELF by `tools/android_asm_convert.py`), the model the Android build already uses. 64-bit instructions with 32-bit pointers, so the decompiled code runs unchanged on Apple Silicon. macOS has no 32-bit support, so the x86 build is not an option.
- **Vendored C libraries** (`port/third_party`): musl maths (for determinism), zlib, expat, opus, stb / stb_vorbis, mbedtls, monocypher, kcp, miniupnpc, tomlc17, smaa, extract-xiso.

## macOS Host (new)
- **Swift + Xcode / Apple SDK (macOS 26, arm64)**: the app shell (AppKit), windowing, keyboard and mouse input (AppKit events; no gamepads), audio, lifecycle, the .app bundle, and the **Metal** renderer replacing D3D8-on-OpenGL. The rendering imports become Metal calls.
- **Rust (stable, via Nix) + UniFFI**: the low-level host runtime, moved over from the Android host by degrees (guest loader, memory reservation, threads, import dispatch) behind a narrow C ABI (`port/macos/runtime`: the memory plan, page tables and image checks, its header made by cbindgen), with UniFFI bindings to Swift from the app track on. Kept portable so a wasm32 target stays possible.
- **The VM host today is C** (`port/macos/host`): the vCPUs, the EL1 vectors, the import dispatch (generated by `tools/macos_dispatch.py`), Linux system calls carried out with Darwin's, and the Android host's SDL bridge. A hosted headless game made about 500 000 exits a second (`HALO_HOST_IMPORT_COUNTS`); with the clock, errno and the memory watch answered in the guest (writes tracked with the VM's stage-2 page protection, `host_watch.c`) and rendering in batches, it makes about 24 000.
- **C++17 for Jolt Physics** (`port/third_party/jolt`, MIT, v5.6.0): the cosmetic ragdolls, dismemberment and debris (track `ragdolls_jolt_20261020`). Jolt runs in the host, built single-threaded with `JPH_CROSS_PLATFORM_DETERMINISTIC` and without fused multiply-add, so runs repeat exactly. It is reached only through a C interface of our own (`port/macos/host/physics/physics.h`, its one C++ file `physics.cpp`); the rest of the host stays C. The guest talks to it through one import a game tick and a shared region (`port/macos/include/host_physics.h`). **Added 2026-10-20.**
- **C and assembly** where the guest/host boundary needs it: the guest's import stubs and its EL1 exception vectors, and the host's Hypervisor.framework calls.
- The guest must live below 4 GB (Xbox memory at `0x80000000`–`0x88000000`, the image up to `0x8c000000`). **Settled (2026-10-18, `docs/macos_host.md`):** an arm64 macOS process cannot map below 4 GB. A small page-zero gets the process killed at exec, and a normal process can't allocate there. The kernel also overwrites `TPIDR_EL0`. So the guest cannot share the host's address space, as it does on Android. Hypervisor.framework works: a VM maps and runs code at `0x80000000`, with an exit to the host costing about 1 µs. **Decided (2026-10-18):** the host runs the guest in a VM under Hypervisor.framework (entitlement `com.apple.security.hypervisor`). Host imports become `svc` → `hvc` exits through the generated import stubs, so the game's sources do not change. Rendering will be sent in batches through shared memory.

## Build & Toolchain
- **Nix (flake)**: the primary dev shell (Rust, ninja, Python, lld, clang with the `arm64_32` target) for quick iteration. `nix build` produces the final build that closes out a track. The SDK is nixpkgs' `apple-sdk_26` (deployment target 26.0); the host is signed ad hoc with sigtool and the hypervisor entitlement; the packages are `guest` and `host` (`nix build .#host`).
- **Xcode's Swift toolchain and SwiftPM**: the Swift app (`port/macos/app/Package.swift`, built with `xcrun swift build` from ninja), XCTest, Metal shader compilation and code signing (`/usr/bin/codesign`); `tools/macos_app.py` lays out the .app. It runs under Nix as the host's impure Apple toolchain (no sandbox): nixpkgs' Swift cannot link against the macOS 26 SDK.
- **configure.py + Ninja**: stays for the guest image during the transition.
- **Python 3**: build scripts, generators (menus, settings, assets) and tests.

## Testing
- **pytest**: the asset-free harness (`tools/harness`, run in the VM) and the map checks; `tools/test_macos_*.py`: the build graph, guest programs in the VM, and the game headless (hosted, and joined on loopback aliases).
- **XCTest**: the Swift layer. **cargo test**: the Rust crates.
- **The frame-time log** (`HALO_HOST_FRAME_LOG`) and `tools/test_macos_benchmark.py` (bloodgulch at 4K for 60 s): performance against the 4K / 120fps target; Metal frame capture and Instruments when a cost needs finding.

## Removed
- Linux, Windows, Android and web builds and their platform code (`port/windows`, the Android Java app, `port/web`, Emscripten, Gradle), as the migration allows. The Android guest runtime is the exception: it is reused.

## Roadmap
- Metal ray tracing (hardware RT on M3 and later) for the lighting engine, once the Metal renderer is in place.
- A wasm32 target for the Rust layer.
